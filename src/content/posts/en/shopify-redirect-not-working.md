If a Shopify redirect does not work, first check whether the source URL still displays a valid page. The native tool works with broken URLs; saving a rule does not force an active page to disappear.

You can spend an afternoon changing the destination and recreating the rule... while the problem sits at the source.

Let’s save that afternoon.

## Start with the old address

Open the exact URL you want to redirect outside the theme editor. Retain the domain, path and any additional parts of the address. A similar URL is not the same test.

Shopify’s [redirect documentation](https://help.shopify.com/en/manual/online-store/menus-and-links/url-redirect) says a valid source page prevents the native redirect from working. It also documents restrictions for reserved routes and collection tag filters. Not every address supports the same treatment.

Before buying an app, record what the source does: loads a product, displays a category, shows an error or already changes address. These are different problems requiring different decisions.

## Is the product finished, or just its stock?

A product returning next week and one retired permanently are different situations. Deleting the former also changes the journey for people who saved its link.

Do not make that decision solely to remove a red line from a report. Consider whether the page can still help: explain availability, clarify compatibility or present a genuine alternative. Its content depends on your operation and promises you can fulfil.

For permanent retirement, ask what someone following the old link expected. That URL may appear in a quote, support email or wholesale reference list. This affects customers as well as Google.

## Choose the destination as a buyer would

Hypothetical example: you discontinue a work shoe and introduce a replacement. Compare sizing, use and features before redirecting. If the replacement is unsuitable for the same purpose, convenience does not make it equivalent.

I would use this decision order:

| Situation | Proposed destination or review |
| --- | --- |
| The same product moved | Its current product page |
| A relevant replacement exists | Its page, with differences made clear |
| Alternatives exist without an equivalent | A category supporting comparison |
| No reasonable alternative exists | Consider retaining the removal and providing guidance on the error page |

This is an editorial and commercial framework, not automation executed on a store.

And for fuck’s sake, do not send everything to the homepage. Someone looking for a particular spare part did not ask to start your catalog again.

## A 404 is not always an emergency

An important page that should work needs attention. A removed URL without replacement is a different case.

Google’s [HTTP status documentation](https://developers.google.com/crawling/docs/troubleshooting/http-status-codes) explains that it stops using URLs returning 4xx errors over time. Correct responses communicate content status; irrelevant destinations need not disguise every retirement.

Do not promise rankings will be preserved simply because a redirect exists. Verify behaviour and monitor changes without selling a guarantee the rule cannot provide.

## Prepare a test record, not a wish list

Before bulk changes, complete a small sample:

| Detail | What to record |
| --- | --- |
| Old URL | Full address used by customers |
| Current state | Actual response when opened |
| Reason | Rename, retirement or replacement |
| Proposed destination | Specific page and justification |
| Observed outcome | Final address and displayed content |
| Internal links to update | Menus, guides or campaigns |

This is a proposed protocol. It does not establish that your configuration was tested or that a server fault exists.

Try another browser if an old rule appears to persist: Shopify notes that permanent redirects can be cached. For multiple markets or languages, test the addresses those buyers use rather than declaring success after one version.

## Redirects do not replace updating your links

If your own guide points to a retired product, update that link too. People should reach useful content without travelling through a history of catalog changes.

The article on [filters and catalog pages](/en/blog/online-store-filter-seo/) helps decide what deserves its own URL. If changing platforms, include these decisions in your [Shopify migration](/en/services/shopify-migration/) before launching.

Start today with three old URLs and complete the record. If you cannot justify each destination in a sentence, you do not yet need hundreds of imported rules: you need to decide what buyers should find.
